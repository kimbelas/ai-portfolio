How this works

A plain-English tour of the Retrieval-Augmented Generation (RAG) system behind the chat. ← back to the assistant

The core promise: it answers only from a set of documents, with citations, and says “I don’t know” when the answer isn’t in them. It never free-associates from the model’s general knowledge. That’s what makes it trustworthy for real docs.

The two phases

A language model has no memory of your documents. RAG works by finding the relevant passages at question-time and pasting them into the prompt.

INDEX (once, when docs change)          ASK (every question)
  documents                               your question
     │ split into chunks                     │ embed the question
     ▼                                       ▼
  chunks → embed each → store            retrieve the most relevant chunks
  (vectors in a store)                   (hybrid search, then rerank)
                                            │ build a grounded prompt
                                            ▼
                                         LLM writes an answer FROM those chunks,
                                         cites them, or says "I don't know"

How relevant chunks are found

Retrieval runs in three stages — each covers a weakness of the last:

  • Semantic search — the question and every chunk are turned into vectors (embeddings); closeness in that space means similar meaning. Great for paraphrases (“can staff read my files” ↔ “zero-knowledge”).
  • Keyword search — plain term overlap. Catches exact tokens embeddings can miss (SOC 2, AES-256, a part number).
  • Hybrid fusion (RRF) then a cross-encoder reranker — the two rankings are fused, and a second model re-scores each (question, chunk) pair together for a precise final order.

Why it won’t answer outside the docs

The model is instructed to use only the retrieved passages and to reply “I don’t know based on the provided documents” when they don’t contain the answer. Try asking the built-in demo “Who is the CEO?” — that fact isn’t in the docs, so it declines instead of inventing one. Every answer also lists the source passages it used, so you can verify it.

Bring your own documents

Drop a PDF, Markdown, or Word (.docx) file on the home page. It’s parsed, chunked, embedded, and stored as a separate, isolated knowledge base — the assistant then answers only from your files, never mixing in the built-in docs or anyone else’s upload. Nothing is persisted server-side beyond the session.

How it’s measured

Retrieval and answer quality are scored on a labeled eval set (not vibes). Adding the cross-encoder reranker moved the numbers measurably:

hybrid (RRF)93%93%
hybrid + rerank100%100%

Answer correctness (LLM-judged) rose 93% → 100% — the reranker fixed a real retrieval miss.

Under the hood

  • Language: TypeScript (Node)
  • Generation: Groq (OpenAI-compatible) — provider-agnostic
  • Embeddings + reranker: on-device via Transformers.js (no data leaves for retrieval)
  • Retrieval: hybrid (semantic + keyword, RRF) → cross-encoder rerank
  • Store: in-memory vector store (graduates to pgvector)
